## 🔴 КРИТИЧНО — Может сломать бот прямо сейчас

### 1. `ImportError` при запуске — `create_excel` и `count_tenant_excel` не существуют

**Файл:** `handlers/admin_group.py`, строка 23  
**Файл:** `handlers/admin_documents.py`, строка 14

```python
from handlers.excel_tg_test import admin_indicators, create_excel, get_volume_and_amount_month, count_tenant_excel, create_word
```

Функции `create_excel` и `count_tenant_excel` **определены** в `excel_tg_test.py` (строки 217, 226), но есть риск, что они возвращают `None` или содержат ошибки — при вызове в реальной отправке бот упадёт с `TypeError` на этапе отправки документа.

**Последствие:** при нажатии «Отправить» весь цикл рассылки завершится с необработанным исключением.

### 2. Дублирование состояния `waiting_for_unexpected` в `admin_states.py`

**Файл:** `states/admin_states.py`, строки 30 и 42

```python
waiting_for_unexpected = State()  # строка 30
...
waiting_for_unexpected = State()  # строка 42 — дубль!
```

В Python второй `State()` молча перезаписывает первый. Это приводит к тому, что FSM-переходы, завязанные на это состояние, работают непредсказуемо — обработчик может не сработать или сработать не тот.

### 3. `final_list` вместо `final` в `create_word`

**Файл:** `handlers/excel_tg_test.py`, строка 662

```python
["Холодная вода", str(final[1][0]), str(final_list[1][1]), ...]
```

Переменная `final_list` не определена в области видимости функции `create_word` — только `final`. При генерации документа для холодной воды будет `NameError` → функция возвращает `None` → файл не создаётся → бот отправляет ошибку арендатору.

---

### 4. Excel-файл открывается без lock — конкурентная запись

**Файл:** `handlers/excel_tg_test.py` — 16 вызовов `load_workbook` / `wb.save`

При одновременной отправке нескольких арендаторов (`proceed_with_final_save` проходит по всем в цикле) несколько корутин могут одновременно открыть и записать один и тот же `ГИРА_1006теккаа2.xlsx`. Результат — **повреждённый Excel-файл**. `file_lock = asyncio.Lock()` объявлен в `admin_group.py`, но в `excel_tg_test.py` **не используется**.

---

### 5. Соединения с БД не закрываются при ошибке

**Файлы:** все handlers — везде используется паттерн:

```python
conn = await asyncpg.connect(config.db_connection)
result = await conn.fetch(query, *params)
await conn.close()
```

Если `conn.fetch()` выбрасывает исключение — `conn.close()` никогда не вызывается. Соединения накапливаются. При достаточной нагрузке PostgreSQL начнёт отказывать в новых подключениях.  
**Нужен `try/finally` или `async with`.**

## 🟠 СЕРЬЁЗНО — Деградация функционала

### 6. Планировщик спама работает каждую минуту, а не каждый час

**Файл:** `main.py`, строка 65

```python
trigger=CronTrigger(hour="*", minute="*")
```

`hour="*", minute="*"` — это **каждую минуту**, не каждый час. Если арендатор не оплатил, он получает сообщение 1440 раз в сутки. Должно быть `minute=0` (раз в час) или вообще другой интервал.

---

### 7. Новый арендатор не получает задачи в планировщике

**Файл:** `main.py` — `setup_scheduler()` вызывается **один раз при старте** бота.

При добавлении новой компании через Admin → Добавить компанию, для нового пользователя задачи (напоминания об оплате, показаниях, счета) **не регистрируются** в планировщике. Они начнут работать только после перезапуска бота.

---

### 8. Глобальные переменные `collected_data` и `temp_documents` — состояние гонки

**Файл:** `handlers/admin_group.py`, строки 354–355

```python
collected_data = {}
unexpected_expenses = 0.0
temp_documents = {}
```

Если два администратора одновременно начнут подавать показания — данные перемешаются. Эти переменные не привязаны к конкретному admin-пользователю, а хранятся глобально для всего процесса.

---

### 9. Голый `except:` без обработки — ошибки проглатываются

**Файл:** `handlers/admin_group.py` — 37 мест вида:

```python
except:
    pass
```

При сбоях в критических местах (сохранение в Excel, запись в БД, генерация документа) ошибка нигде не логируется и не сообщается пользователю/админу. Отладка при проблемах в продакшне становится невозможной.

---

### 10. `get_sheet_name_in_id_business` — `UnboundLocalError` если нет результата

**Файл:** `handlers/excel_tg_test.py`, строка 59–64

```python
async def get_sheet_name_in_id_business(id_business):
    results = await get_data('SELECT sheet_name FROM bussines WHERE id = $1', id_business)
    if results:
        for list_item in results:
            sheet_name = list_item['sheet_name']
    return sheet_name  # ← UnboundLocalError если results пустой
```

Если компания не найдена — `sheet_name` не определена и функция падает с `UnboundLocalError`. Это происходит при любой попытке сгенерировать документ для несуществующего арендатора.

---

### 11. Excel-операции выполняются в основном потоке асинхронного цикла

**Файлы:** `handlers/excel_tg_test.py`, `handlers/admin_group.py`

Большинство операций с `openpyxl` и `pandas` (`load_workbook`, `pd.read_excel`, `wb.save`) выполняются **синхронно** прямо в асинхронных функциях. Это блокирует event loop на время чтения/записи файла. При большом Excel-файле бот перестаёт отвечать на другие сообщения на несколько секунд.

## 🟡 ВАЖНО — Ухудшает надёжность

### 12. Отсутствует пул соединений к PostgreSQL

Каждый `get_data()`/`new_data_insert()` открывает новое соединение `asyncpg.connect()` и закрывает его. При активном использовании это создаёт сотни коротких соединений. Нужен `asyncpg.create_pool()`.

---

### 13. Регистрация команды администратора хранится в открытом виде в коде

**Файл:** `handlers/admin_group.py`, строка 28

```python
ADMIN_REGISTRATION_COMMAND = "/ГИРОАДМИН12409@hklz9(*bv"
```

Команда прямо в исходном коде — если код когда-либо попадёт в публичный репозиторий или к третьим лицам, любой человек сможет зарегистрироваться как администратор. Должна быть в `.env`.

---

### 14. Нет валидации chat_id при работе с admin-обработчиками

Некоторые admin-обработчики проверяют `message.chat.id != ADMIN_CHAT_ID`, но не все. Теоретически пользователь, угадавший callback_data, может вызвать admin-действие.

---

### 15. Scheduler — `spam_scheduler` стартует даже если уже запущен

**Файл:** `main.py`, строка 70

```python
if not scheduler.running:
    scheduler.start()
```

Если `scheduler` уже запущен — новые задачи добавляются корректно, но при `replace_existing=True` задача для одного пользователя пересоздаётся каждый раз при нажатии "не оплатил". Это нормальное поведение, но при сбое планировщика задача может задвоиться.

---

### 16. `delete_in_excel` — синхронная запись без lock

**Файл:** `handlers/excel_tg_test.py`, строка 66

```python
async def delete_in_excel(name_tenant):
    wb = load_workbook('docs/ГИРА_1006теккаа2.xlsx')  # синхронно, без lock
    ...
    wb.save(...)
```

Нет ни асинхронности (`run_in_executor`), ни блокировки. При параллельном удалении двух компаний файл повредится.
